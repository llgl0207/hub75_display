### ARM 与可编程逻辑

两种版本都是 Zynq-7000 SoC，包含 **双核 ARM Cortex-A9，最高 667 MHz**，以及可编程逻辑（PL）：

| 版本 | 芯片 | LUT | DSP | Block RAM | DDR3 |
|---|---|---:|---:|---:|---:|
| 7010 | XC7Z010-1CLG400C | 17,600 | 80 | 2.1 Mb | 512 MB |
| 7020 | XC7Z020-2CLG400C | 53,200 | 220 | 4.9 Mb | 1 GB |

其他板载资源包括 256 Mbit QSPI Flash、Micro SD、USB、HDMI；Wi-Fi/蓝牙和 MIPI CSI 仅在手册标注的 **7020 版本**提供。

### 网口能否使用？

**可以。** 板上有 RJ45 网口，PHY 为 RTL8211E，通过 RGMII 连接到 Zynq PS 的 Ethernet MAC；手册的网口章节称支持 **10/100/1000 Mbps**。不过手册概述处另有“10/100”描述，存在不一致；如果你需要确认实际协商速率，建议上板后查看 PHY/系统网卡状态。Linux 下通常要使用匹配该板的设备树/驱动配置；裸机则需配置 PS Ethernet 和 PHY。

### 🤖 AI

可以把它理解为两条并行的路径：**无线网卡通常由 PS 上的软件驱动；PL 通过 AXI 接口与 PS、DDR 交换数据**。不必把 Wi‑Fi“做进”PL，除非你有特殊的高速数据处理需求。

## 无线网卡怎么驱动？

MIZAR‑Z7 手册确认 7020 版本有 Wi‑Fi/Bluetooth 模块和陶瓷天线，但没有在手册文字中明确列出模块型号及其与 Zynq 的具体接口。因此，**不能只凭天线判断具体芯片、总线或驱动**；这些需要核对板卡修订版对应的原理图，或者从厂商提供的 Linux 镜像、启动日志里确认。[MIZAR‑Z7 用户手册](https://fpga-docs.microphase.cn/zh-cn/latest/DEV_BOARD/MIZAR-Z7/MIZAR-Z7_Reference_Manual.html)

一般来说，Wi‑Fi 是由 **ARM 端操作系统和驱动**管理的：如果有适配这块板的 Linux 镜像，先启动系统，再查看启动日志和网卡列表，确认模块是否被识别、是否缺驱动或固件。Vivado 负责硬件设计和 PS 配置，**通常不负责直接提供 Wi‑Fi 驱动**。

## PL 做的硬件如何给 PS 使用？

常见做法是在 Vivado 的 Block Design 里，把 PL 模块接到 Zynq 的 AXI 接口上：

- **PS 访问 PL 控制寄存器**：让 PL 提供 AXI4-Lite 从接口。ARM 软件就能读写寄存器，例如设置参数、启动计算、读取状态。
- **PL 通知 PS**：PL 可以通过中断通知 ARM，告诉它任务完成或有事件发生。
- **PL 与 DDR 交换大量数据**：给 PL 配置 AXI master，或使用 AXI DMA，通过 Zynq 的 PS‑PL 高性能接口访问 DDR。AMD 的 Zynq 示例展示了通过 AXI DMA 和 HP 端口，在 PL 与 PS DDR 之间搬运数据。[AMD：AXI DMA 经 HP 端口传输数据示例](https://adaptivesupport.amd.com/s/article/54941?language=en_US)

大致结构是：

```text
ARM 软件 ──AXI-Lite──> PL 控制寄存器
ARM 软件 <──中断────── PL 完成通知

PL 逻辑 <──AXI / DMA──> DDR
          （经 PS-PL 接口）
```

## PL 能直接读 PS 使用的内存、不占 CPU 搬数据吗？

**可以，但不是“任意地址自动可读”。** PS 和 PL 可以共同使用 DDR；需要在硬件里建立对应的 AXI/DMA 通路，并由软件配置 DMA、缓冲区地址和传输长度。配置完成后，数据搬运可以由 DMA/PL 完成，**CPU 不必逐字节复制**，但 CPU 通常仍负责启动任务、管理缓冲区和处理中断。

还要注意：

- DDR 带宽是 PS 和 PL **共享**的，DMA 不占 CPU 搬运时间，并不代表不占 DDR 带宽。
- 经常用的 HP 路径通常需要软件正确处理缓存一致性；裸机要做相应的 cache flush/invalidate，Linux 应使用 DMA API 管理缓冲区。
- Zynq 还提供 ACP 等缓存一致性路径，但需按设计和性能需求选择，不能只因启用了接口就假设所有缓存问题都自动解决。

如果你是刚开始上手，推荐先用 **PS AXI‑Lite 控制一个简单 PL 模块**，确认 ARM 能读写寄存器；再做 AXI DMA 和 DDR 缓冲区传输；Wi‑Fi 则单独从厂商 Linux 镜像验证。

**可以接入 MCP 做很多自动化，但通常不是 Vivado/Vitis 原生装上 MCP 后就能无人值守完成全部开发。**常见模式是：MCP 服务器把 AI 的请求转成 Tcl、命令行或工程 API 操作，再调用本机工具。社区已有面向 Vivado 的 MCP 项目，例如 [vivado-mcp](https://github.com/mapleleavessssssss-wq/vivado-mcp) 和 [vivado_mcp](https://github.com/coreyhahn/vivado_mcp)；也有面向 Vitis 的社区项目 [vitis_mcp](https://github.com/QingquanYao/vitis_mcp)。它们不是 AMD 官方支持保证的功能，兼容性、安全性和维护状态要逐个评估。

### 适合自动化的环节

在你这块 MIZAR‑Z7 上，可以考虑让 AI/MCP 协助：

- 创建或检查工程、添加 RTL / XDC / IP；
- 调用 Vivado 批处理运行综合、实现、生成 bitstream；
- 收集并总结错误、告警、资源利用率和时序报告；
- 调用 Vitis 的构建流程，编译 ARM 端应用；
- 将仿真、综合、构建结果整理成可追踪的日志。

MCP 负责**编排和调用工具**；Vivado/Vitis 本身仍是执行综合、实现和编译的工具。AI 根据报错修改设计后，也应重新运行验证流程。

### “全自动”需要谨慎理解

自动跑完一次构建，不等于工程正确，更不等于板子可用。器件型号、时钟、引脚约束、PS 配置、DDR、启动镜像和驱动等都需要针对板卡核实；最终还得通过仿真、时序检查和上板测试确认。尤其是下载 bitstream、改启动介质、擦写 Flash 等有副作用的操作，建议设置为**明确确认后才执行**。

2. **观察启动阶段**
   正常情况下，日志会逐步出现 BootROM/FSBL、U‑Boot、Linux 内核启动信息，最后出现登录提示或 shell。不同镜像的文字会不同，不必要求每个阶段的提示完全一致。

   ```sh
   uname -a
   mount
   ip link
   dmesg | tail -n 80
   ```
   能进入 shell，根文件系统成功挂载，且 `dmesg` 没有持续报存储或驱动错误，基本可认为启动成功。网卡是否出现可用 `ip link` 检查；没有无线接口不一定代表启动失败。
