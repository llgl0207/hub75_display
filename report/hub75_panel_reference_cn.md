## 1. 屏幕结构参数（实测）

| 项目 | 参数 | 说明 |
|---|---|---|
| 分辨率 | **128 × 64** | 每行 128 像素，共 64 行 |
| 扫描方式 | **1/32 扫描（ABCDE 5 位地址）** | 每帧 32 个地址，每个地址同时点亮上下两行 |
| 并行数据组 | **双 RGB**：R1/G1/B1 与 R2/G2/B2 | 每组地址刷新时，两组数据同时输出 |
| 数据深度 | 每色 1 bit（无灰度） | 灰度需 FPGA 侧用 BCM/PWM 自行实现 |
| 亮度控制 | OE 低有效，PWM 调光 | **OE 高 = 灭，OE 低 = 亮** |
| 单色/整屏 | 支持任意 RGB 组合 | `r/g/b` 为开关量 |
| 实测功耗特性 | 全白为最坏工况 | 供电不足会表现为区域不亮/颜色异常 |

**行映射关系（已实测确认）：**

- 地址 `address`（0～31）对应 **上半屏第 `address` 行**
- 同一地址同时输出 **下半屏第 `address + 32` 行**
- 因此一帧需要 32 次地址切换，覆盖全部 64 行

**列移位关系（已实测确认）：**

- 每行需要移入 **128 个像素时钟**
- 先移入的像素落在**远离输入连接器**的一端；最后移入的像素靠近连接器
- 等价描述：发送顺序为 `x = 127 → 0`（递减），`x = 0` 是离 HUB75 连接器最近的列

**未使用的数据线：**

屏幕接口上存在 R3/G3/B3、R4/G4/B4，但本屏 **不使用**，驱动中始终输出低电平。FPGA 移植时可直接忽略。

## 2. 信号定义与电平

| 信号 | 方向 | 极性/有效沿 | 作用 |
|---|---|---|---|
| CLK | 输出 | **上升沿采样数据** | 像素移位时钟 |
| LAT（STB） | 输出 | **上升沿锁存** | 将移位寄存器内容送显示 |
| OE | 输出 | **低有效**（高 = 灭） | 输出使能，PWM 调光 |
| A/B/C/D/E | 输出 | 高电平为 1 | 行地址，bit0～bit4 |
| R1/G1/B1 | 输出 | 高 = 亮 | 上半屏（当前地址行）RGB |
| R2/G2/B2 | 输出 | 高 = 亮 | 下半屏（地址 + 32 行）RGB |

STM32 参考引脚（仅作对照，FPGA 可自由分配）：

| 信号 | STM32 引脚 | 信号 | STM32 引脚 |
|---|---|---|---|
| CLK | PH2 | A | PI4 |
| R1 | PH4 | B | PI5 |
| G1 | PH5 | C | PI6 |
| B1 | PH6 | D | PI7 |
| R2 | PH7 | E | PI11 |
| G2 | PH8 | LAT | PI9 |
| B2 | PH9 | OE | PI10 |

## 3. 时钟与时序参数（推导）

### 3.1 时钟链

```
HSE 25 MHz
  → PLL1: /5 × 192 /8  = 120 MHz  (SYSCLK)
  → AHB  /2            = 60 MHz   (HCLK)
  → APB2 /2            = 30 MHz   (PCLK2)
  → TIM1 时钟 = 2×PCLK2 = 60 MHz  (APB 分频≠1 时定时器时钟翻倍)
```

### 3.2 行节拍（一个地址 = 8 拍）

| 参数 | 值 | 计算 |
|---|---:|---|
| TIM1 计数时钟 | 6 MHz | 60 MHz / (PSC+1) = 60/10 |
| 单计数时间 | 166.67 ns | 1 / 6 MHz |
| 单拍时间 | **50 µs** | (ARR+1) × 166.67 ns = 300 × 166.67 ns |
| 每地址拍数 | 8 | `HUB75_PWM_STEPS` |
| **单地址（一行）时间** | **400 µs** | 8 × 50 µs |
| 每帧地址数 | 32 | `HUB75_SCAN_ROWS` |
| **整帧时间** | **12.8 ms** | 32 × 400 µs |
| **刷新率** | **78.125 Hz** | 1 / 12.8 ms |

> 78 Hz 偏低，肉眼可能察觉轻微闪烁。FPGA 侧建议提高到 **≥ 120 Hz**，即整帧 ≤ 8.33 ms，单地址 ≤ 260 µs。

### 3.3 单个地址内的动作顺序

在一个地址周期（400 µs）内，8 个节拍的分工：

| 节拍 | OE | 动作 |
|---|---|---|
| phase 0 | 高（灭） | ① OE 拉高消隐 ② 移入 128 个像素 ③ 更新 A~E 地址 ④ LAT 上升沿锁存 |
| phase 1～6 | 高（灭） | 仅保持消隐，等待 |
| phase 7 | 低（亮） | 点亮该地址对应的上下两行 |

因此 `OEp = 7` 时，每行实际点亮时间为 **50 µs / 400 µs = 12.5%**。

**亮度调制关系（8 档）：**

| `OEp` | 点亮拍数 | 占空比 | 相对亮度 |
|---:|---:|---:|---|
| 0 | 8 | 100% | 最亮 |
| 1 | 7 | 87.5% | |
| 3 | 5 | 62.5% | |
| 4 | 4 | 50% | |
| 6 | 2 | 25% | |
| 7 | 1 | 12.5% | 默认 |
| 8 | 0 | 0% | 全灭 |

关系式：**点亮占空比 = (8 − OEp) / 8**。

### 3.4 移位时钟 CLK 时序

代码中每个像素的 CLK 周期结构：

```
数据建立 → CLK 拉高 → 延时 → CLK 拉低 → 延时
```

延时由 `HUB75_PinDelay()` 提供，即 **8 个 `__NOP()`**，共 3 段延时/像素。

| 参数 | 估计值 | 依据 |
|---|---:|---|
| 单个 NOP | ≈ 8.3 ns | 120 MHz 主频 |
| 单段延时 | ≈ 67 ns | 8 × 8.3 ns（未计 GPIO 写开销） |
| 单像素 CLK 周期 | **≈ 200～300 ns** | 3 段延时 + 2 次 ODR 写入 |
| CLK 频率 | **≈ 3～5 MHz** | 由上式反推 |
| 整行移位耗时 | **≈ 26～38 µs** | 128 × 200～300 ns |

> 结论：**移位必须在 50 µs 的单拍时间内完成**，当前实现约占 52%～76%，余量偏紧。FPGA 用硬件移位可轻松压到 1～2 µs。

### 3.5 时序参数汇总（FPGA 约束用）

| 参数 | 建议值 | 说明 |
|---|---|---|
| CLK 频率 | 1～10 MHz | 本屏 3～5 MHz 已验证；频率越高刷新越快 |
| CLK 高/低脉宽 | ≥ 50 ns | 保守取值，满足常见 HUB75 驱动芯片 |
| 数据相对 CLK 上升沿建立时间 | ≥ 20 ns | 数据先稳定再打 CLK |
| 数据保持时间 | ≥ 20 ns | CLK 下降沿后再改数据 |
| LAT 脉宽 | ≥ 100 ns | 本实现 8 NOP + 2 次 ODR 写 |
| LAT 上升沿前 CLK 静默 | ≥ 100 ns | 防止误移位 |
| LAT 上升沿到 OE 拉低 | ≥ 100 ns | 避免锁存瞬间出现拖影 |
| OE 高/低脉宽 | ≥ 100 ns | PWM 最小步进 |
| 每地址移位像素数 | **128** | 固定值 |
| 每帧地址数 | **32** | 固定值 |

## 4. 一帧的参考时序流程

```
帧开始
│
├─ addr = 0 ─────────────────────────────────────────────
│   ├─ OE=1（消隐）
│   ├─ for i = 0..127:  输出像素(x=127-i) → CLK 上升沿
│   ├─ A..E = addr 的 5 位二进制
│   ├─ LAT 上升沿（锁存）
│   ├─ OE 消隐保持 OEp 拍
│   ├─ OE 拉低（点亮 8-OEp 拍）
│   └─ 保持至 8 拍结束
│
├─ addr = 1 … 30 （同上，地址递增）
│
├─ addr = 31
│
└─ 回到 addr = 0（下一帧）
```

要点：

1. **地址必须在数据移完之后才改变**，移位期间地址保持为上一行的值。
2. **OE 在整个移位+锁存期间必须为高（灭）**，否则会出现横向亮线拖影。
3. **LAT 上升沿之后才允许 OE 拉低**。
4. 地址为 `addr` 时，输出的两组数据分别对应第 `addr` 行与第 `addr+32` 行。

## 5. 像素数据映射

### 5.1 屏幕坐标 → 数据

给定屏幕坐标 `(x, y)`，`x ∈ [0,127]`，`y ∈ [0,63]`：

```
addr = y % 32            // 0..31
半屏 = (y >= 32) ? 下 : 上

若 半屏 == 上：  addr = y,       数据走 R1/G1/B1
若 半屏 == 下：  addr = y - 32,  数据走 R2/G2/B2
```

### 5.2 发送顺序

对当前 `addr`，按 `x` 从 127 递减到 0 依次送出：

```
for x = 127 downto 0:
    上组数据 = {R1, G1, B1} = pixel(x, addr)        // y = addr
    下组数据 = {R2, G2, B2} = pixel(x, addr + 32)   // y = addr + 32
    CLK ↑
```

即：**同一列的上、下半屏像素在同一时钟沿并行送出**。

### 5.3 常见坑

- 若图像左右镜像，说明 `x` 递增/递减方向搞反。
- 若上下半屏内容互换，说明 R1/G1/B1 与 R2/G2/B2 接反，或 `y ± 32` 的偏移方向错。
- 若图像上下颠倒且分块错位，检查地址递增方向（`addr` 0→31 还是 31→0）。
- 若只有部分行亮，优先检查 **E 地址线是否连接**（本工程曾因漏接 E 导致只有 1/4 区域亮）。

## 6. FPGA 迁移实现建议

### 6.1 推荐架构

```
          ┌──────────────┐
像素时钟 → │  时序状态机   │ → CLK / LAT / OE / ADDR
          │  (扫描控制)   │
          └──────┬───────┘
                 │ 当前 addr、当前列 x
          ┌──────▼───────┐
          │  帧缓存读取   │ ← 双口 BRAM（128×64×3bit 或带灰度）
          └──────┬───────┘
                 │ {R1,G1,B1} / {R2,G2,B2}
                 ▼
              HUB75 引脚
```

### 6.2 状态机建议

| 状态 | 动作 | 建议时长 |
|---|---|---|
| `S_LATCH` | OE=1，LAT 脉冲，更新地址 | ≥ 100 ns |
| `S_SHIFT` | 循环 128 次：放数据 → CLK 高 → CLK 低 | 128 × CLK 周期 |
| `S_BLANK` | OE=1 保持（亮度暗段） | 参数化 |
| `S_ON` | OE=0 保持（亮度亮段） | 参数化 |

`S_BLANK + S_ON` 之和即单地址显示时间。亮度 = `S_ON / (S_BLANK + S_ON)`。

### 6.3 参数化建议

| 参数 | 建议 | 说明 |
|---|---|---|
| `H_ACTIVE` | 128 | 每行像素数 |
| `V_SCAN` | 32 | 地址数 |
| `ADDR_BITS` | 5 | A~E |
| `CLK_DIV` | 按目标 CLK 频率设定 | 目标 5～10 MHz |
| `PWM_BITS` | 4～8 | 灰度位宽，越高刷新越慢 |
| `FRAME_HZ` | ≥ 120 | 避免闪烁 |
| `BLANK_AFTER_LATCH` | ≥ 1 个 CLK | 防拖影 |

### 6.4 刷新率与灰度预算

刷新率、灰度位宽、单行时间的关系：

```
单行时间  = 1 / (FRAME_HZ × V_SCAN)
可用 PWM 步进数 = 单行时间 / PWM 最小步进
```

例：`FRAME_HZ = 120`、`V_SCAN = 32` → 单行 260 µs；若 PWM 最小步进 1 µs，则该行可容纳 260 级（约 8 bit）灰度。

若要做高灰度（如 12 bit BCM），需提高 CLK 频率或降低刷新率，或采用「分行独立 PWM + 时间片」方案。

### 6.5 与 STM32 实现的差异提醒

| 项目 | STM32 现状 | FPGA 应改进 |
|---|---|---|
| 移位方式 | CPU 在中断里逐位翻转 GPIO | 硬件状态机，耗时从 ~30 µs 降到 ~1 µs |
| 亮度 | 8 档固定 PWM，绑定行节拍 | 每行独立 PWM，支持真灰度 |
| 帧缓存 | 无（直接算像素） | 双口 BRAM + 双缓冲，避免撕裂 |
| 刷新率 | 78 Hz | ≥ 120 Hz |
| 地址更新 | 移位后软件写 ODR | 状态机自动递增 |

## 8. 旋转体积显示开发约定与性能预算

本节记录讨论确定的方向，不代表当前静态测试 RTL 已实现。职责与工程约束详见 [AGENTS.md](<../../AGENTS.md>)。

### 8.1 职责、几何与术语

- **PL 是完整显示体系**：负责红外捕获、周期估算、角度/切片调度、DDR 读取、解包、BRAM 缓存、帧切换和所有 HUB75 信号。PS/Linux 只生成 DDR 图像并提交完成帧，不参与实时扫描。
- 一次红外触发对应机械一整圈；周期采用最近五个触发间隔的平均值。每次触发立即重置调度时间基准至第 0 片，实际输出在稳定 PL 时钟的安全边界处理。不增加异常剔除、漏触发恢复等复杂机制。
- 转过 180° 后复用相同截面，左右内容对调。采用**方案一：DDR 只存半圈独立数据，PL 后半圈复用并反向取 BRAM 列**。DDR 仍正向突发读取，不要求反向 AXI 搬运。
- **完整屏幕扫描/全切片**：覆盖 128×64 的一次完整扫描，含 32 个行地址、每地址 128 个像素时钟。
- **半圈存储切片**：DDR 中对应半圈某一角度的一份完整屏幕数据。
- **径向半切片**：旋转轴一侧的半屏空间内容，与“半圈存储切片”不是同一个单位。下列数量换算假设旋转轴居中、两侧有效宽度相同。
- 实际旋转方向、角度零点、精确列映射留待上机校准。PS 提供一键上下翻转、左右翻转、顺逆时针切换，作用于下一次生成的帧，不修改当前活动缓冲区。反转角度顺序应保留第 0 片参考；这些测试变换与 PL 后半圈正常复用的列反向不同。

### 8.2 容量上限与扫描缓存

- 预留**半圈最多 400 个独立完整切片**的存储容量，实际使用数量单独配置，不要求达到此扫描数量。
- DDR 采用 RGB 紧密打包，由 PL 解包。推荐顺序为“切片 → 行地址 → 列 → 上下两组 RGB 六位”；确切位序、总线跨字拼接、跨度与对齐待接口设计冻结。
- 每片有效载荷：128×64×3/8 = **3072 B（3 KiB）**。
- 400 片单帧：**1,228,800 B（1200 KiB，约 1.17 MiB）**；DDR 双缓冲约 **2.34 MiB**，不含对齐、元数据和分配器额外开销。
- 采用**整片 BRAM 乒乓缓存**：一组供扫描、一组填充下一片。两片紧密有效载荷共 6 KiB，但这不是最终物理 BRAM 使用量；解包后的内部位宽、存储组织、FIFO 和 DDR 服务延迟需综合与测量验证。
- PS 写完并完成 DMA/cache 同步后提交；PL 在红外重启边界采用新帧基址，并保持一圈内不变。具体提交/预取就绪/确认协议仍待设计。
- 帧切换不能直接取消已发出的 AXI 读事务；需接收并隔离旧返回数据。只有旧帧读取全部结束，旧缓冲区才能交还 PS 重写。

### 8.3 30 fps 目标及用户提供的 2280 场/秒约束

**目标**：完整体积刷新 30 fps，按一圈一帧计算，需要 **1800 RPM**。尚未声称已实现。

**输入约束**：用户提供完整屏幕场刷新上限 **2280 次/秒**；此处按该值预算，其测试条件及是否为面板绝对上限仍需核实，不用历史静态参考中的保守 CLK 建议反推或替代此值。

设半圈存储的有效完整切片数为 N，体积刷新率为 F：

```text
完整屏幕扫描率 S = 2 × N × F
整圈扫描时隙数   = 2 × N
转速 RPM         = 60 × F
```

在 F=30、S=2280 条件下：

| 指标 | 数值 |
|---|---:|
| 半圈独立完整切片 N | 38 |
| 整圈完整屏幕扫描次数 | 76 |
| 整圈径向半切片位置（按两侧展开计数） | 152 |
| 一圈时间 | 约 33.333 ms |
| 一次完整屏幕扫描时间 | 约 438.596 μs |
| 每行地址平均时间预算 | 约 13.706 μs |

152 个径向半切片是在 76 次完整扫描中显示的，不需要再将场刷新率翻倍。在上述均匀取样且 76 为偶数的配置下，后半圈的径向方向与前半圈重合，因此 **152 是含半圈复用的显示位置次数，不等于 152 个互不重复的径向角度**；独立径向方向为 76 个。半圈复用不会增加独立角度信息。

400 是存储上限，不是上述运行配置。半圈 N=400 时整圈有 800 个扫描时隙，在 30 fps 下需 24,000 次完整扫描/秒，明显高于当前提供的 2280 次/秒约束。

### 8.4 场刷新率与像素 CLK 的关系

每次完整扫描的有效移位脉冲数固定为：

```text
32 × 128 = 4096 个 CLK 脉冲
平均有效脉冲速率 = 4096 × S
```

S=2280 时，平均有效脉冲速率为 **9.33888 MHz**。若移位占总扫描时间的比例为 α，则移位期间实际 CLK 频率为：

```text
f_CLK = 4096 × S / α
```

因此**扫描结构和各阶段时间比例固定时，场刷新率直接决定 CLK 频率及 LAT/OE/行地址节奏**。不能把 CLK 与场刷新率作为互不相关的参数，也不能忽略锁存、消隐、不能重叠的显示等待，直接把平均脉冲速率当成实际移位 CLK。最终时序由周期与有效片数共同导出，并验证脉宽、亮度和时序余量。

### 8.5 红外重启、零度缺片与未来加速补显

- “触发重置到第 0 片”明确的是调度基准，不保证数据尚未准备时第 0 片立即点亮。
- 不在本阶段额外承诺第 0 片专用预取缓存；启动及新帧数据未就绪时的处理方式仍待决定。
- 若每次启动都跳过最早几片，可能使零度附近固定一段内容长期不可见。用户要求未来考虑**短时间加速补显并追上正常角度时间轴**，而不是把永久丢弃这些片作为最终方案。
- 此功能本阶段不实现，也不固定“五六片”的追赶窗口。补显会带来局部角度偏移、压缩、亮度变化，需要结合上板结果权衡。
- 加速追赶需要额外扫描速度余量；正常扫描若已用满 2280 次/秒上限，就没有追赶余量。需降低正常运行片数或重新验证短时扫描上限，不能只靠控制逻辑获得额外速度。
- 上电尚无周期、最近五个间隔未收齐时的默认行为尚未确认。

### 8.6 开发协作与自动化

- 助手优先编写全部 RTL、仿真、PS 软件、必要驱动和构建脚本；用户协助综合/实现、硬件连接、上板及返回日志和测量结果。编写完成不等于硬件验证完成。
- Vivado 优先通过 Tcl 自动化；无法直接执行时，提供完整命令或 GUI 中明确的操作步骤。典型形式：`vivado -mode batch -source <脚本路径>`。
- Vitis 接口依实际安装版本选择：旧版 XSCT/Tcl 或 Unified IDE Python CLI，先确认可用性再生成脚本。
- MCP 可选，不阻塞开发。已搜索到 [AMD Ross 官方下载页](https://www.amd.com/en/support/downloads/ross-agentic-ai.html)和 [Xilinx Ross Vivado MCP 工具说明](https://github.com/Xilinx/ross-ai-assistant/blob/main/docs/reference/vivado-mcp-tools.md)，但本次未能获取页面正文，本机版本、Windows、Vitis 与聊天客户端兼容性及接入状态均未验证，不能据此声称已经连接。
